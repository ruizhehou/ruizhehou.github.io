模型开始接手几天的活：Fable 与 Codex GPT-5.5 的分岔

如果说过去两年大模型的竞争，核心问题是「谁答得更准」，那么 Anthropic 的 Claude Fable 5 和 Codex 里的 GPT-5.5，把问题推进到了另一个层面：谁能更稳定地接手一段复杂工作，并把它做成可交付结果。

这不是一次简单的模型参数对比。Fable 更像一个被安全边界包起来的高自治专家；Codex GPT-5.5 更像一个深度接入开发环境的工程协作者。前者强调「把长任务交出去」，后者强调「把模型放进真实工作台」。

一、Fable 先把长任务接起来

Anthropic 在 2026 年 6 月 9 日发布 Claude Fable 5，把它定位为面向广泛用户开放的 Mythos-level 模型。官方页面给它的关键词非常明确：最困难的知识工作、编码问题、长时间异步任务，以及过去模型难以持续完成的复杂项目。

这说明 Fable 的目标不是让用户多问几轮，而是让用户敢把一段完整工作交出去。Anthropic 明确提到，在 Claude Code 或 Claude Managed Agents 这类 agent harness 中，Fable 可以连续工作数天：跨阶段规划、委派子任务，并检查自己的工作。这个描述很关键，因为它把模型能力从「回答质量」拉到了「任务持久性」。

Fable 适合的场景也很清楚：大型代码迁移、复杂实现、多日 autonomous session、企业知识工作、深度研究，以及包含图表、表格、PDF、界面截图的视觉理解。尤其是视觉能力，Anthropic 把它放在 coding workflow 里讲：模型不仅看文档，也看自己实现出来的界面是否符合目标。

但 Fable 不是完全无遮挡的 Mythos。Anthropic 同时发布的 Claude Mythos 5 与 Fable 共享底层能力，但 Mythos 主要面向 Project Glasswing 下的受信任客户；Fable 则带有更强的安全分类器。涉及网络安全、生物、化学等敏感方向时，Fable 请求可能被路由到 Claude Opus 4.8。官方还要求使用 Fable 接受 30 天数据留存，用于安全监控。

所以 Fable 的本质是：把更高自治能力开放给通用用户，但用更强的安全路由把边界框起来。这对普通知识工作和大多数工程任务影响不大，但对安全研究、逆向分析、生命科学等双用途任务，用户会明显感受到边界。

二、Codex 把模型放进工作台

GPT-5.5 在 Codex 里的重点，不只是「模型更聪明」，而是「模型更会使用开发环境」。OpenAI 在 2026 年 4 月 23 日发布 GPT-5.5 时，把它描述为面向真实工作的模型：写代码、调试、在线研究、分析数据、创建文档和表格、操作软件，并在多个工具之间移动直到任务完成。

放到 Codex 里，这个定位就变得很具体：模型不是孤立生成答案，而是在「读仓库、改文件、跑命令、读错误、继续 patch」的循环中工作。OpenAI 公告明确说，GPT-5.5 已向 ChatGPT 和 Codex 用户推出；在 Codex 中，它面向 Plus、Pro、Business、Enterprise、Edu 和 Go 计划开放，提供 400K 上下文窗口，并有 Fast mode。

如果看 API 层面，GPT-5.5 的规格也很强。OpenAI 的模型文档显示，gpt-5.5 支持文本和图像输入、文本输出，API 上下文窗口约 1M token，最大输出 128K token，并支持 Web search、File search、Code interpreter、Hosted shell、Apply patch、Skills、Computer use、MCP、Tool search 等工具能力。

这就是 Codex GPT-5.5 的产品差异：它的优势不只在模型本身，而在模型被放进了完整的工程工作流。对开发者来说，真正重要的是它能否定位到正确文件、理解周边影响、跑出失败用例、再把补丁收敛到可验证状态。

只看表格，Fable 的上下文、输出和长周期定位非常强；Codex GPT-5.5 的价格、工具链和工程闭环更有吸引力。但如果只把它们放在同一张参数表里，反而会漏掉最重要的区别：一个是在提高「可交接任务」的上限，一个是在提高「真实工作流」的完成率。

Anthropic 自己的 Fable 页面强调 coding、knowledge work、vision、computer use 上的 state-of-the-art；OpenAI 的 GPT-5.5 页面则强调 agentic coding、computer use、knowledge work 和科学研究。两边都在争同一块高地：模型不再只是回答问题，而是开始承担行动。

四、怎么选择

如果你的目标是把一个模糊、复杂、多阶段的问题交给模型，比如「理解一个大型系统后完成迁移方案」「读一批 PDF 和表格后形成可审阅报告」「连续几天推进一个高不确定性的研究任务」，Fable 更值得优先尝试。它的设计目标就是长时间自治和高难度交付，1M 上下文、128K 输出和更强的跨模态理解，都会对这类任务有帮助。

但如果你的工作现场是代码仓库、终端、测试、patch、浏览器和本地环境，Codex GPT-5.5 可能更顺手。它不一定在所有 benchmark 上都领先，但它更贴近工程师每天真实的闭环：定位问题、修改代码、跑测试、读报错、继续修。再加上 GPT-5.5 API 价格低于 Fable，长期使用时成本优势也更明显。

可以用一个更直接的判断：

  • 任务像「整包外包」：优先看 Fable。重点是模型能否在低监督下持续推进。
  • 任务像「工程结对」：优先看 Codex GPT-5.5。重点是模型能否在仓库、终端和测试之间稳定闭环。
  • 任务涉及敏感安全或生命科学方向：要提前考虑 Fable 的 fallback 和数据留存要求。
  • 任务会产生大量 token 成本：要把 GPT-5.5 更低 API 单价和 Codex 实际上下文窗口一起算。

五、真正的分水岭

Fable 与 Codex GPT-5.5 的竞争，不只是 Anthropic 和 OpenAI 谁的旗舰模型更强，而是下一代 AI 工作方式的两个方向。

Fable 代表的是「把复杂任务交给模型」：模型要能长时间保持目标、拆解阶段、调用工具、检查结果，并在用户低干预的情况下推进。Codex GPT-5.5 代表的是「把模型放进真实工作台」：模型要理解项目结构、遵守本地约束、跑真实命令、修改真实文件，并把输出变成可验证的工程结果。

一句话概括：Fable 像是一个更敢接整包复杂工作的自治专家；Codex GPT-5.5 像是一个嵌在开发环境里的高能力同事。

下一阶段的模型竞争，可能不再是单纯比较谁回答得更漂亮，而是谁能在你的上下文、工具、权限和安全边界里，把事情持续做完。
